## ⚠️ 先看两条最容易忽略的配置

> 这两条不看，脚本会「看起来在跑、实际什么都不做」或「一直重试到天亮」。

### 1. 炉石必须用**全屏模式**，不要用「最大化窗口」

程序的点击坐标是按 **1920×1080 全屏** 写死的。窗口化 / 最大化时，窗口客户区与全屏画面存在偏移，**所有点击会整体错位**：

- 下随从因为有吸附，看上去还能成功；
- **法术指定目标会持续失败重试**（一直打不出牌）。

请在炉石里设置：`设置 → 选项 → 显示 → 显示模式 = 全屏`，同时桌面分辨率 **1920×1080**、Windows 缩放 **100%**。

### 2. 换战网账号后，必须同步更新「用户 ID」为**完整昵称（含 #编号）**

脚本完全靠昵称区分敌我（日志里 `TAG_CHANGE Entity=你的昵称 ...`）。昵称与当前账号不一致时，**整局都会被判成「对手回合」而一张牌都不出**，日志里也看不出报错。

现在脚本会自己校验并提示：读到对局日志中的玩家名后自动比对，不一致时

- 网页顶部弹出橙色横幅、基础配置卡片下方标红；
- 日志与右上角浮窗打出 `⚠️ 用户 ID 与日志玩家名不匹配` 并显示日志里的真实昵称（可直接照抄）。

## 🩺 存活检测（挂机防空转）

**为什么需要**：挂机时如果炉石在换牌界面闪退，旧版本察觉不到，会继续对失效画面做 OCR 重试，可能空转好几个小时（实测约 2 小时 47 分）直到手动停止。

**现在怎么判**（每个状态机循环都检查一次）：

| 信号 | 判定 | 处理 |
| --- | --- | --- |
| `Hearthstone.exe` **进程消失**（本轮确实见过它） | 6 秒宽限后仍未回来 → **已退出** | 日志 + 浮窗**红色醒目告警**，**自动停止**自动化 |
| 对局中 `Power.log` **超过 120 秒**没有新内容 | 疑似卡死 | 黄色告警（继续观察，不停机） |
| 对局中 `Power.log` **超过 300 秒**没有新内容 | **无响应** | 红色醒目告警 + **自动停止** |

细节说明：

- 进程信号是**权威**信号（闪退、被关、被杀都能立刻发现）；日志信号只在对局中参考——匹配对手/选主职业阶段日志本来就安静，用它会误判。
- 进程枚举失败（无权限等）时按「无法判定」处理，**绝不会**因此停机。
- 告警文案会带上上下文（最近一次自动化诊断、连续推荐读取失败次数），方便判断「到底卡在哪一步」。
- 阈值可在网页「🩺 存活检测」卡片里改（默认 `120s 告警 / 300s 自动停止`），也可以整体关闭。

告警长这样：网页顶部红色横幅 + 浮窗里红色加粗的 `⚠️ 炉石已退出：Hearthstone.exe 进程消失…自动化已自动停止。`（截图见上方「界面预览」）。

开启后，**每次在对局中识别盒子意见并执行完**之后：

3. 最后仍然复位到左上角复位点 `(70, 60)`。

## ⏱️ 抽牌额外延时（每张 1s）

抽牌会连带**手牌入场动画 + 盒子面板刷新**，读太早容易照着旧的推荐出牌。所以只要在**我方回合**里手牌变多，就按张数多等一会儿（默认 **1 秒/张**）：

| 情况 | 是否延时 |
| --- | --- |
| 每回合开始那一下的**常规抽 1 张** | ❌ 不算（那 1 张是免费的） |
| 同一回合一次抽到 **2 张及以上** | ✅ 多出来的每张 +1s（抽 2 张 → +1s，抽 3 张 → +2s） |
| 回合内**任何操作**触发的抽牌（打出的牌抽牌、战吼/发现给牌…） | ✅ 每张 +1s |
| 对手回合里我抽到牌 | ❌ 不算（那会儿脚本也没在出牌） |

- 判定依据是 Power.log 里的**手牌入场数**（`ZONE→HAND` 的累计次数），不依赖识别盒子画面；
- 免费的那 1 张只让给「我方本回合还没动作过」时出现的手牌增加 —— 这样即使 Power.log 晚几拍、出牌抽到的牌先被看到，也不会被误当成免费那张；
- 每个回合步骤开始、以及每次动作执行完都会各查一次，日志晚写出来的抽牌也能补上；
- 延时写进日志与浮窗：`[SYS] 抽到 2 张牌，额外延时 2.0s 后继续`；
- 可在网页「⏱️ 延时设置」的 **抽牌额外延时（秒/张）** 里改，填 **0 = 关闭**（关闭时连那次额外检查都不做，节奏与旧版一致）。

## 🗿 泰坦（Titan）技能

泰坦随从不能攻击，改成「点自己场上的泰坦 → 弹出三张技能牌（和抉择/发现同一套居中面板）→ 选技能 →（技能要目标时）再点目标」。盒子对这类牌给的指令长这样：

```text
操作1号位泰坦
兵主
目标是对方2号位
穆克拉先生
选择卡牌
鲜血符文
```

程序的执行顺序固定为**点泰坦 → 点技能 → 点目标**（与上面文字的行序无关），随后盒子会刷新出下一步推荐（兵主结算后会「发现一张对应符文的牌」，就是普通的 `选择我方N号位卡牌`），继续照做即可。

技能点哪个位置**不靠猜**：优先用 Power.log 里这张牌当前的 `option/subOption`（下标就是面板从左到右的位置），其次是本局学到过的技能顺序，最后才是实测确认过的静态兜底表；三者都对不上就**只重试、不乱点**。

## 🐙 古神（Old God）技能

古神随从同样不能攻击，操作方式和泰坦一样：**点自己场上的古神 → 弹出四张技能牌（和泰坦/发现同一套居中卡牌布局）→ 选技能 →（技能要目标时）再点目标**。区别只有一条：**古神一回合里可以连着选多次**，所以每用掉一个技能，盒子会紧接着给出下一个技能，程序继续照做即可（不用结束回合）。

盒子对这类牌使用的是「攻击」句式 + 「选择卡牌」：

```text
操作1号位随从攻击
克苏恩，帝国之眼
目标是对方2号位
小鬼奶奶
选择卡牌
克苏恩的凝视
```

判定规则：**「操作N号位随从攻击」后面跟着「选择卡牌」就一定是古神技能**（真攻击永远不会带选择行）；目标行可选，我方/对方的随从与英雄都支持。

四张技能牌点哪一张也不靠猜：古神的技能子牌 id 是「主牌 id + t + 数字」，数字升序就是面板从左到右的槽位，直接从 `cards.json` 读出来（克苏恩 = 愤怒/领域/凝视/仆从，尤格-萨隆 = 头脑/疯狂/崛起/领域，恩佐斯 = 召唤/操纵/大军/领域，亚煞极 = 凝视/子嗣/威力/领域）。Power.log 的 `subOption` 序号在有技能用过之后会被重排（不可用的挪到末尾），所以**不能**拿它当点击下标。

每个技能每局只能用一次：日志里已经打过 `ACTIVATABLE_MINION_ABILITY_USED_n` 的技能会被直接拦下（`old_god_ability_already_used`），不会重复点；技能是否真的结算了，也按这个标签（外加场面/手牌/水晶变化）确认，没确认就等盒子刷新，不重复点同一张牌。

### 选完技能还要点目标（`选择对方N号位卡牌`）

古神的衍生牌（克苏恩的子嗣、滑行者巨怪的战吼、克苏恩仪式）是「先选一项技能，再按技能指向目标」两段式。第一段盒子说 `选择我方N号位卡牌` + 技能名（和发现同形）；选完之后游戏会进入**指向选择**（Power.log 里是 `ChoiceType=TARGET`），盒子这时给的是：

```text
选择对方2号位卡牌
小鬼奶奶
```

这行是**动作行**（不是 `目标是…` 修饰行），号位是**对方场面的位置**（实测 08:57:50：选择框里实体顺序是 [2号位, 1号位]，盒子说的 2 号位就是场面第 2 个）。程序现在会直接点对方场面第 N 个；`选择对方英雄`、`选择我方N号位卡牌`（我方目标）、`选择我方英雄` 也都支持。

> 这一行以前没被语法识别，而 OCR 的稳定读取会用「规范化后是否还有字」判断面板是否在场——整段文字被规范化清空，于是那 42 秒一直被判定为 `recommendation_not_stable`（面板读不到字），回合白白耗掉。现在这行是合法动作行，不会再被清空。

**盒子 2026-10-29 更新后的文案**（实测 23:01 截图）直接给出点击序列：

```text
进行拼装【右2中1】
鸭妈妈
```

## 🎴 出牌：以盒子面板为准

出牌时「点哪张、点哪个目标、要不要找落点」这些**行为**现在一律按盒子面板的文字执行（面板说的是「法术 / 随从 / 武器 / 地标 / 英雄」+ 有无「目标是…」），日志状态只用来校验「这一手还是不是同一张牌」。

原因：日志里的手牌顺序会错位——`发现`/生成进手牌的牌经常**没有 `ZONE_POSITION` 标签**，排序时被当成 0 号位排到最前面，整只手牌的顺序就跟着错。错位本身不影响点击位置（盒子给的槽位号就是游戏里的槽位），但会让程序拿错牌的**类型**去做后续动作：

- 实测 2026-10-29 22:35：面板说「打出1号位法术 潮起潮落 / 目标是对方1号位 滑行者巨怪」，状态把 1 号槽认成了英雄牌「灭世者死亡之翼」→ 走了英雄牌分支 → 只点了手牌和屏幕中间、**目标被丢掉**，游戏一直停在「等你点目标」，最后只能手动点掉。
- 同一局的 22:32 还有反过来的：面板说「打出1号位随从」，状态那一槽是法术 → 没去点落点。

现在这类不一致会打一行诊断：

```text
[提示] 手牌类型与面板不一致：面板=SPELL 状态=HERO 槽位=1（CATA_190h），按面板执行
```

另外两点配套改动：

- `PlayCardAction` 的类型来自面板；`ManualController` 校验手牌时只比卡号/实体号，不再比类型（否则状态滞后时会把正常的一手直接拒掉）；
- 执行器改成 `ClickExecutor()`（不再显式传 click 模块），`[SPELL]`/`[CLICK]` 现场快照恢复输出——之前那次「法术没点目标」就是因为少了 `[SPELL]` 行，只能靠点击坐标反推。

## 🧪 环境自检

**第一次启动脚本会自动自检一遍**，之后随时可在网页顶部「🧪 环境自检」卡片点 [🔍 重新自检]。明细列表**可以收起**（点卡片右上角「收起」，选择会记在浏览器里；一旦有 ❌ 会自动展开，不会把问题藏起来）。

| 检查项 | 怎么判 |
| --- | --- |
| Python 版本 | 必须 **3.12 的 64 位**：装了别的版本（尤其 3.13/3.14）会直接判 ❌ 并给出建环境命令 |
| 依赖包 | 逐个 import 一遍，并和 `requirements.txt` 的版本比对；缺哪个直接给 `pip install` 命令 |
| 管理员权限 | 不是管理员 → 鼠标/键盘点击会被系统拦掉（现象就是「脚本在跑但点了没反应」） |
| 屏幕分辨率 / 缩放 | 必须是 **1920×1080 / 100%**，否则硬编码坐标会整体偏移 |
| 炉石窗口 | 没开只算 ⚠️（点「开始运行」会先拉起战网和炉石） |
| 炉石日志目录 | 目录不存在算 ❌；目录在但还没有 Power.log 只算 ⚠️（打一局就有了） |
| OCR 模型目录 | 没下载只算 ⚠️，首次识别会自动下载 |

结论会同时写进控制台日志（❌/⚠️ 逐条带修复提示），自动化出问题前的第一步排查就从这里看。

## ⚠️ 启动前检查

- [ ] 盒子推荐打法位于屏幕左侧
- [ ] 桌面 / 炉石分辨率均为 **1920 × 1080**，Windows 缩放 **100%**
- [ ] 炉石显示模式为 **全屏**（`设置 → 选项 → 显示`），**没有**使用「最大化窗口」
- [ ] 「用户 ID」填的是**当前账号的完整战网昵称（含 #编号）**——换过账号一定要同步改
- [ ] 网页「🧪 环境自检」里没有 ❌（Python 3.12、依赖、管理员权限、分辨率全绿）
- [ ] 用浮窗「校准」确认盒子面板落在绿框内（提示条变成绿色「已检测到盒子面板」）
- [ ] 炉石盒子使用**简体中文**，左侧「推荐打法」完整显示
- [ ] 炉石 / 炉石盒子窗口未被其他窗口遮挡
- [ ] 使用**管理员权限**启动 Python，`HEARTHSTONE_LOG_ROOT` / `YOUR_NAME` 配置正确
- [ ] 「🩺 存活检测」保持开启（默认开启），避免炉石闪退后无人值守空转
